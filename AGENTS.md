# Agent Rules

Canonical instructions for every coding agent in this repo. `CLAUDE.md` only imports this file.
Project context and the reasons for the stack: [docs/PLAN.md](docs/PLAN.md). Use `pnpm`, never `npm` or `yarn`.

## 1. Layers (enforced by `pnpm depcruise` and ESLint)

- **`packages/shared`**: Zod schemas, inferred types and `as const` dictionaries. Nothing else: no
  functions, no classes, no Node modules, npm only `zod`. It is the single source of truth (SSOT)
  for every contract between the API and its clients.
- **`apps/api`**: `src/core` is pure, deterministic logic without I/O (no Hono, no database, no
  queue, no AI provider, no clock, no random: the caller passes them in). It also defines the ports
  (interfaces) that adapters implement. `src/routes` are thin adapters: parse input with Zod,
  delegate to the core, format the response. `src/adapters` hold everything that talks to the outside
  (database, queue, object store, AI providers) behind a port of the core.
- **Web preset (apps/web, optional, not part of the core)**: the boundary rules for it already exist in
  `config/dependency-cruiser.cjs`. It talks to the API only through the contracts of `packages/shared`
  and `import type` of the API's app type.
- **SoC beats DRY.** Similar code in two independent features is fine. Extract only on the third
  identical use (Rule of Three). No speculative abstractions, no meta-frameworks (YAGNI).
- Fail fast: adapter and provider errors throw. No silent `catch`, no fallback data in production paths.
- Filtering, search and aggregation run in the database, never by loading whole tables into Node.
- Strict types: no `any`, no `@ts-ignore`, no `as unknown as`, no `export *`, no `unknown` as a
  parameter type (parse at the boundary with Zod; `cause` and type-predicate subjects are exempt), no
  `unknown` return type, no dictionary of `unknown`, `any` or `object` (`Record<string, unknown>` is
  allowed only as a generic constraint), and no widening a value to `unknown` and asserting it back.
  Every type assertion except `as const` needs a `// SAFETY: <invariant>` comment. Derive types with
  `z.infer`, never write a parallel type by hand.
- No module mocking in tests (`vi.mock`, `jest.mock`): pass dependencies in or use MSW.
- Constants: a value that steers logic (status, type, role) is an UPPER_SNAKE value in an
  `export const X = {...} as const` dictionary and is imported everywhere, tests included
  (`pnpm audit:magic`).

## 2. Invariants

1. **Contract first.** Every request and response shape is a Zod schema in `packages/shared`. Routes
   validate input with it; tests parse output with it.
2. **Ports and adapters.** Every adapter passes the contract test of its port. A new adapter is done
   when the contract test of its port (a shared test function that the adapter tests register) passes against it.
3. **Env only through `apps/api/src/config/env.ts`.** Only `parseEnv` turns `process.env` into
   config. Entry points hand the environment to it; nothing else reads it. Never print or edit `.env*`
   files and never commit them; only `.env.example` is tracked.
4. **No real network calls in tests.** MSW rejects every unmocked request. Record provider answers once
   and replay them. Live calls exist only in explicit scripts that say so in their name.
5. **No content in logs.** Log IDs, lengths, durations and counts only, as structured JSON lines.
   No `console`.
6. **Idempotency.** An operation that a client or a queue may repeat (a POST with a client key, a
   job) must be idempotent. Name the key in the contract.
7. **Migrations** are generated by the tool (drizzle-kit) once a database adapter exists, never
   hand-edited. A breaking change ships in three steps (expand, backfill, contract) so that the
   running version and the next one both work.
8. **Load numbers are measured, not estimated.** Every feature with a service-level claim (a rate
   limiter, a queue, an endpoint with a latency target) gets a k6 scenario in `load/` and a row in
   [docs/LOADTEST.md](docs/LOADTEST.md) with numbers from `pnpm load`.
9. **Verify before deciding.** Never rely on memory for library APIs, image tags, prices or limits.
10. **Docs stay portable.** Relative links only, no absolute machine paths, no test counts. A change
    to a path listed in `docs/docs-map.json` needs its document, or `Docs: n/a, <reason>` in the
    commit message (`pnpm audit:docs` checks links and script names).

## 3. Workflow

- `pnpm check` and `pnpm test` must pass before you finish. The Stop hook and the Husky hooks run them.
- Prefer small commits. Never skip hooks (`--no-verify`) and never force-push; the guard blocks both.
- Work directly on `main`: no pull requests. The ruleset only blocks deleting `main` and force-pushes; the CI
  checks run after the push, so check the run and fix a red one at once.
